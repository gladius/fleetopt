Same command, same tools, same proof. Only the name changes.

Two kinds of thing. On the left, what changes from run to run: the expert. It is a folder of markdown, fetched from the central catalogue when a developer names it, with no code in it. Its header says which model it runs on, which shared tools it uses, and which other experts it may call. On the right, what never changes: the session, the tools, the probe and the gate. They ship with fleetopt and are the same whichever expert is loaded. So adding an expert is writing a folder, and switching experts is changing one word on the command line. An expert can name a tool or a rule; it cannot bring its own, which is why it cannot loosen its own proof.
