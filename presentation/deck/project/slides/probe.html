How it sees the team's agent: the probe

1 · Driver

Starts the team's graph in its own Python, from its folder, with its env files

2 · Hook

Loaded as Python starts. Adds a LangChain tracer and notes each compiled graph

3 · Record

Each step is written to a file as it ends, so a crash still leaves what happened

4 · Store

Loaded into SQLite when the run ends; the session reads it with SQL

Recorded for every model call

  • The node, and its path when graphs are nested
  • Model and provider
  • Tokens in, out and read from cache
  • Prompt size, duration and any error

What it never does

  • Edit a line of the team's code
  • Replace or switch off their own tracing
  • Change how the agent runs
  • Show the session the value of a key or secret
For the technical audience. The probe is how numbers get into the system. The driver is a small script that runs inside the team's own interpreter and calls their graph for each request. The hook is picked up by Python as it starts; it registers a tracer beside whatever tracing the team already has, and takes a snapshot of each graph as it is compiled: its nodes, its edges, and where each node's code lives. Every step is appended to a file the moment it ends, and loaded into SQLite afterwards. Today it sees LangGraph agents whose model calls go through LangChain.
