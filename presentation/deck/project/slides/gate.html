The gate: how a change is proven

Kept only if all of these hold

  1. Better past the noise, over three runs each side
  2. Nothing that passed the team's checks now fails
  3. A separate model finds no answer worse
  4. No change to code the requests never ran
  5. The team's tests and evals are untouched

Checked against, strongest first

  1. The team's own eval suite, run before and after
  2. A golden dataset with expected answers
  3. Examples of what the agent is sent
  4. Requests written for the run, and labelled so

The session that made a change never grades it. Code and a separate reader do.

Enforced in code, never asked

No push · no installs · edits only on its own branch · the agent never run by hand · caps on time and spend

This is the part nothing else has. A change is kept only when five things hold. One: the measured cost, tokens or time is better by more than the original varies with itself, over three runs each side. Two: nothing the team's own checks passed before now fails. Three: a separate model, which sees only the answers before and after, finds none worse. Four: the change does not touch code that the requests never ran, because nothing would have proven it. Five: the team's tests and evals are untouched. What it is checked against depends on what the project has, strongest first; requests written for the run are the last resort and the report says so. The band at the bottom is what the tools and hooks enforce whatever the session wants.
