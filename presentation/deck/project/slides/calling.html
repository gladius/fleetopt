One expert can call another

Cost expert

Finds the project has nothing to check its agent against

The call

Code starts the tester in a session of its own, and waits

Tester

Reads the code and writes requests that reach each route

Cost expert

Carries on with the answer, and reports where the requests came from

The rules

  • An expert's header names whom it may call
  • The called expert only reads; it changes nothing
  • Two calls a run at most, and the spend is counted

Why not one big agent

  • Each session holds one expert's prose, never two
  • The caller waits, so no answer is lost
  • The answer is kept with the run, for anyone to read
Experts reach each other in two ways. First, through files: when the design expert has reviewed an agent, the cost expert's next run on the same code is handed that review. Second, through a call, shown here. The cost expert found a project with no tests and no examples. Its header says it may call the tester, so it did. Code started the tester in a separate session with only the tester's own prose; the tester read the project, changed nothing, and returned requests that reach each route. The cost expert carried on, and its report says the requests were written for the run and are not the team's. This ran end to end on a project with no examples. There is no orchestrator agent: code starts the second session and the caller waits for it.
