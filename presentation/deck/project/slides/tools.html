The tools: what the session can do

ToolWhat it does, and its limit
askOne question to the developer while getting started; three at most
startTries the team's agent on one request, under the probe; four tries
measureRuns it three times, records every call, compares with the last kept code
queryRead-only SQL over everything that was recorded
checkedCloses one check on one node, with the number that settles it
callHands a task to another expert in its own session and waits; two at most
run evalsRuns the team's own eval command, the same one before and after
save changeCommits one change, named in plain words, on its own branch
keepThe gate: keeps what was saved only if it is proven
undoBack to the last kept code, or drops the changes named
shapeDesign expert only: what the graph declared against what it did
For the technical audience. These are the only ways the session can act on the team's agent. The session decides when to call each one and with what; the code inside decides what happens and where it stops. Keep is the gate. Shape is the one tool that belongs to a single expert: an expert's header names the extra tools it uses, and it can only name tools that exist.
