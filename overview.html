Central AI team

fleetopt

Sends an expert to a team's AI agent, measures what the agent does, and keeps only what the team's own checks prove.

One command on the developer's machine, in their own setup. Cost, design, security, red team, tester: each an expert written centrally as prose, each judged by a number. Several can go at once.

What a team needs ready

  • The project in gitChanges land on a new branch; nothing uncommitted is touched
  • The agent runsIts own setup, env files, keys and services, found by name
  • Something to check againstTheir eval suite (any tool), a golden dataset, or even one example request
  • Visible model callsThrough LangChain, in a LangGraph graph

It uses the strongest check the project has. With none, the cost expert can call the tester to write requests, labelled as written. If what it needs is missing, it says what it looked at and stops before spending: Nothing to check the agent against: add evals, a golden dataset or an example of what it is sent.

How it works · one command, unattended

  1. Survey

    Once a project: every agent, how each starts, what checks it

  2. Start

    The shipped agent, as the survey proved it

  3. Measure

    3 runs, every model call recorded, cost past the noise

  4. Find

    What the expert looks for, in the recordings and the code

  5. Change

    With apply only: each fix saved on a branch

  6. Prove

    Measure and evals again; keep or undo, by code

  7. Report

    Findings with numbers, checks closed, and the card

Looks again after each kept change

The experts · one folder of prose each, judged by a number

  • costWhere the agent wastes tokens and money: growing context, repeated work, the wrong model, tools it never usesreview and apply
  • designWhether the design fits the job: branches never taken, a supervisor that always picks the same order, a review loop that changes nothingreview
  • securityWhat it can do with whose credentials, what reaches its model unchecked, what leaves the process, what it pulls inreview
  • redteamWhat a hostile request makes it do, judged by what it did in the recordingsreview
  • testerThe requests that would check it: those the project holds and those worth writing; called by cost when a project has nonecalled
  • surveyorWhat the project holds: every agent, how each starts, proven; runs by itself the first time, and when the files changeautomatic

Inside · one Claude session, set up as the expert asks

Guide

How to work: a part every expert shares, and each expert's own. The header names what it is asked, what a change must earn, which experts it may call. It can name a rule or a tool; it cannot bring its own.

What an expert knows, and the list it must close: for every node that matters, each of its checks, opened by code from the recording. It cannot shorten the list.

In the code · fleetopt/

cli.py the command · config.py signs in the way Claude Code does on the machine; no key of its own · scope.py one run's state, in its own task, so a process holds several

the session · and its experts

  • session.pyThe one Claude session: guards, model, the run, the tape of every message, several experts at once
  • tools.pyThe 11 tools every expert uses, with the limits, the checks and git inside them
  • expert.pyFinds an expert's folder here or pulls it from the central catalogue; holds the rules a change must meet
  • census.pyWhat the project holds, walked by code before any model sees it: agents, env files, launchers, evals
  • card.pyThe agent card, assembled from the records after every run; no model writes a word of it
  • ../experts/The catalogue, outside the code. Prose only, one folder an expert

probe/ · runs and records

  • driver.pyStarts the team's graph in their own Python, with their env files and folder
  • hooks/Records every model call, without editing their code
  • runner.pyOne run, stopped if it never ends or runs away
  • store.pyThe records, in SQLite

evidence/ · what counts

  • measure.py3 runs, medians, only a change past the noise counts
  • pricing.pyTokens to dollars, per model and provider
  • judge.pyThe separate reader: did anything break
  • shape.pyWhat the graph declared against what it did: nodes, edges, branches taken
  1. SurveyThe census by code, then the surveyor proves how each agent starts; kept in .fleetopt/ until the project changes
  2. StartThe proven entry for the shipped graph; start tries one request, several agents at once
  3. Measurerun evals on the original when there is a suite, then measure: 3 runs, every call recorded, the checks opened
  4. Findquery the recorded calls and read the code, with the skills; checked closes each cell with its number
  5. ChangeWith apply: each fix its own save, a named commit on fleetopt's branch
  6. ProveOne measure and evals for all; keep only if better and nothing broke, else undo and split
  7. ReportIts account with the numbers, a summary computed by code, the run's log and tape, the card; the team's copy is back as it was

What keeps it safe

  • Never touches a team's live code
  • Kept only if better past the noise and the team's own checks still pass
  • Every finding carries a number from the recording
  • A person decides what is merged
For LangGraph agents in Python, with model calls through LangChain. Checked against the team's own evals (any tool), a golden dataset, or examples of what the agent is sent. Records live with the project in .fleetopt/: the survey, how each agent starts, every run, the agent card.
