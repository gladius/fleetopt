## Part C - picks

For the first four LangGraph targets I would take **memory-agent** (single ReAct + store, one Anthropic key, no search, behavioural tests), **data-enrichment** (ReAct + reflection checker, structured output checked by tests; Anthropic + Tavily), **agents-from-scratch** (triage router + ReAct + HITL + memory on one OpenAI key, with the only real expected-tool-call dataset in the set), and **open_deep_research** (supervisor spawning parallel researcher subgraphs, `init_chat_model` configurable, OpenAI + Tavily, Deep Research Bench evals) - that covers ReAct, reflection, router/HITL and supervisor with at most one LLM key plus Tavily and no databases. `react-agent` is the smoke test before any of them; `langgraph-swarm-py/examples/research` is the cheap add for the swarm pattern once its keys are confirmed; `deepagents/examples/deep_research` replaces open_deep_research if archived status is a problem, at the cost of a third key. The two most likely over-built designs worth reviewing are **executive-ai-assistant** (two providers across nodes, gpt-4o on every step including triage, separate Anthropic reflection graphs that rewrite prompts, a cron ingestion graph and Agent Inbox HITL - for drafting email replies) and **gpt-researcher/multi_agents** (eight roles including a reviewer -> reviser loop and a separate publisher agent, all on gpt-4o from `task.json`); on the ADK side `financial-advisor` is the equivalent smell (a coordinator whose four workers always run in the same order).
